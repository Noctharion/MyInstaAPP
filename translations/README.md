# MyInsta language packs

These packs localize MyInsta's own interface from v27.0.1 onward. The app follows Instagram's selected language, including Follow system. English and European Portuguese are bundled for offline first use; other languages use the existing HTTPS pack download and cache mechanism.

The current authoring catalogue has **2,132 entries: 2,106 strings and 26 plurals**, at source revision **5**, synchronized with the application bundle of v27.0.1 beta 5. All **50 authoring files contain the full key set**: on 2026-10-30 the 460 entries missing from each of the 48 other files were translated, entries whose English wording changed were revised, and 36 entries no longer used by the application were removed. Existing translations were otherwise preserved. No entry was filled with copied English. No new locale was added: the 45 primary catalogues and five documented system identity variants cover the same 48 unconditional native selector variants confirmed in the original Instagram 447.0.0.55.81 ARM64 base. Six additional flag-gated native languages remain unconfirmed and outside that denominator. See the [locale manifest](review/2026-10-17/locale-manifest.json) and [sharing decisions](review/2026-10-17/variant-sharing.json).

**Authoring and downloadable delivery are separate.** The existing immutable pack files and index remain unchanged at revision **1**, with **1,598 entries** each. Source, translator template and context match the current application catalogue; preparation/release of updated downloadable packs remains pending. New keys in an older downloaded pack use English fallback. English and pt-PT are synchronized with the corresponding application bundle; an APK containing those updates is needed for offline use of the new interface text. No changed bytes were written under an old immutable pack path.

All current delivery revisions are **1**, with one current runtime pack file per locale. This owner-requested reset targets a clean install of v27.0.1; previous revision pack files were retired. Strict revision/hash validation remains enabled. A development cache holding a higher revision does not accept a lower revision as an ordinary update. Future corrections must increase the locale revision and use a new immutable hash path.

Coverage, technical validation, AI review, human review and Android acceptance are separate. The [per-locale table](review/2026-10-17/COVERAGE.md) records the earlier revision-1 delivery review; its independent-review flags do not certify the current wording. The [2026-10-30 synchronization record](review/2026-10-30/README.md) lists, per locale, what was preserved, added and corrected, and the result of an independent AI QA pass over every changed entry. The [translation glossary](TRANSLATION_GLOSSARY.md) records the terminology decisions. Human/native-speaker certification and a full Android language/layout matrix remain pending. These translations remain available for community review and testing.

Start with [source/en.json](source/en.json), [contribute/template.json](contribute/template.json) and [contribute/context.json](contribute/context.json). Translate presentation values while preserving keys, named placeholders, product identities and technical values. The [functional glossary](review/2026-10-17/FUNCTIONAL-GLOSSARY.md) and [recorded locale terminology](review/2026-10-17/LOCALE-CONVENTIONS.md) distinguish local reading, receipts, temporary media, device downloads and separate backup/DevFlags routes.

Use [tools/Translations.ps1](tools/Translations.ps1) to export, validate and prepare contributions with PowerShell and Java 11+. The [contribution guide](CONTRIBUTING.md) explains commands, exact locale priority and script defaults. Public source/context and development review records are separate from runtime packs; private-source access is unnecessary. The optional Python maintenance checker identifies the exact entries needing renewed review after a source, context or translation edit.

Only needed packs are downloaded. The index is checked at most daily with ETag; downloads must pass size, SHA-256, schema and placeholder validation before atomic caching. Failures preserve the last valid cache. Updates apply to newly opened surfaces, preserving dialogs and edits already in progress. APK release artifacts and the public APK update feed are maintained separately.
